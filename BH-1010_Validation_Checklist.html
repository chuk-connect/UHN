1 — Object-Wide Defaults & Sharing Rules
Design Deviation D1 — Sharing Rule Criteria: BH-1010 spec requested Account__c = Running User's Contact.Account__c as the criteria field. Salesforce does NOT support Lookup fields in criteria-based sharing rules (deploy error: "not valid workflow field").
Resolution (Apr 24, 2026): Criteria changed to Status__c notEqual 'Superseded'. Institute scope is enforced through AAR_Evaluators public group membership (the Account relationship is the membership gate, handled by the Record-Triggered Flow on Contact.Is_AAR_Evaluator__c). This pattern aligns with the FCC Experience Cloud sharing decision made on the same date.
Design Deviation D2 — AAR_Submission__c OWD = ReadWrite (not Private): Because AAR_Submission__c uses a Lookup to UHN_AAR__c (not Master-Detail), it cannot inherit OWD from the parent. A Private OWD would require a sharing rule using AAR_Record__c (a Lookup field) as criteria — also unsupported. Resolution: OWD=ReadWrite with access controlled exclusively via permission sets (AAR_Evaluator and AAR_Admin only have object access to AAR_Submission__c; AAR_PI is deliberately excluded).

# Scenario Step-by-Step Expected Result
T1 Evaluator Sees Active AARs 1. Create a test User, assign AAR_Evaluator permission set.
2. Add User to AAR_Evaluators public group (Setup → Public Groups → AAR_Evaluators → Add Members).
3. Login as test User.
4. Navigate to UHN_AAR__c list view. 		User sees all UHN_AAR__c records with Status__c ≠ "Superseded" that they do not own.
T2 Evaluator Cannot Edit AAR Core Fields 1. Login as AAR_Evaluator test user.
2. Open any UHN_AAR__c record.
3. Attempt to edit any standard UHN_AAR__c field (e.g., Status__c). 		Fields are read-only. No edit pencil visible. No save option on standard fields.
T3 Validation Rule Blocks Assessment on Non-Submitted AAR 1. Create an AAR_Submission__c record linked to a UHN_AAR__c with Status__c = "Draft".
2. Login as evaluator.
3. Open the submission. Attempt to update Evaluator_Score__c = 7.
4. Click Save. 		Validation error fires: "Evaluator assessment can only be completed for Submitted AARs."
T4 Validation Rule Permits Assessment on Submitted AAR 1. Create/find an AAR_Submission__c linked to a UHN_AAR__c with Status__c = "Submitted".
2. Login as evaluator.
3. Set Evaluator_Score__c = 8, Evaluator_Comments__c = "Strong submission".
4. Click Save. 		Record saves successfully. No validation error.
T5 Flow: Is_AAR_Evaluator__c → Group Membership 1. Find a Contact with a linked active User.
2. Set Contact.Is_AAR_Evaluator__c = true. Save.
3. Run SOQL: SELECT Id FROM GroupMember WHERE GroupId = '00GAq00000H64QXMAZ' AND UserOrGroupId = '[User.Id]' 		Returns 1 row — User is now a member of AAR_Evaluators public group.
