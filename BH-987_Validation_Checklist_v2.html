On UHN_AAR__c vs AAR_Record__c: Salesforce permanently locks a custom object's API name at creation. There is no metadata path to rename UHN_AAR__c to AAR_Record__c without destroying and rebuilding the object — which would require migrating live records and reworking 124 files containing 1,508 references across 17 profiles, 6 permission sets, flows, approval processes, triggers, and Apex classes. This rename cannot be performed safely in an active sandbox org.

The practical impact is zero: the object label is already "AAR Record"; child objects already expose AAR_Record__c as the lookup field name; no PI or admin user ever sees the API name. This is documented as a permanent architectural note, not a defect.
