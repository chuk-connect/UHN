A1 Navigate to Setup → Object Manager → Search "AAR". Confirm all 21 objects are listed as Deployed. All 21 objects visible: UHN_AAR__c + 20 children listed above. Re-deploy the missing object from force-app/main/default/objects/
A2 Open UHN_AAR__c in Object Manager → Relationships & Lookups. Confirm children: AAR_Submission__c, AAR_Scholarly_Output__c, AAR_Publication__c, AAR_Recognition__c, Commercialization__c appear. All child relationship labels visible. Check relationship field type; Master-Detail vs Lookup.

Child record saves and appears in the related list. Check required field validation rules on UHN_AAR__c. Refer to VR_ validation rules.

Section B — Verification Sync Trigger

# Step Expected Result If Fails — Check
B1 Create an AAR_Scholarly_Output__c record with Is_Verified__c = true. Save. Verification_Status__c = "Verified", Verified_At__c and Verified_By__c auto-populated. Confirm AAR_ScholarlyOutputSyncHandler class is Active in Setup → Apex Classes.
B2 Edit that record and set Is_Verified__c = false. Save. Verification_Status__c resets to "Proposed". Verified_At__c and Verified_By__c cleared. Check clearVerified() method — requires existing status = "Verified" to clear.
B3 Edit a record. Change Verification_Status__c to "Verified" without touching Is_Verified__c. Save. Is_Verified__c = true (Direction B mirror). Verify trigger is Active and handler class compiles cleanly in Setup → Apex Classes.
B4 Run: AAR_ScholarlyOutputSyncHandlerTest in Setup → Apex Tests. All 8 methods. 8/8 pass, 0 failures. Review test debug log for assertion failures.

Section C — Permission Set & Access Verification

# Step Expected Result If Fails — Check
C1 Assign AAR_PI and AAR_PI_Access to a test Standard User. Log in as that user. Create a UHN_AAR__c record. PI can create and view their own AAR record. Cannot view other users' AAR records. Verify OWD for UHN_AAR__c = Private in Setup → Sharing Settings.
C2 Assign AAR_Evaluator + AAR_Evaluator_Access to a second test user. Create an AAR_Reviewer__c junction record linking that user to the PI's AAR. Log in as the evaluator. Evaluator can see and edit the assigned AAR. Cannot see unassigned AARs. Confirm AAR_Reviewer__c.Evaluator__c lookup is set to the user's Id. Confirm Apex Managed Sharing triggers if used.
C3 Assign AAR_Institute_Leadership to a third test user. Log in as that user. Institute leader can see all non-Superseded AAR records. Read-only — no edit buttons. Confirm sharing rule Institute_Evaluators_AAR_Access is active in Setup → Sharing Rules. Confirm user is a member of AAR_Evaluators group (if required by rule).
C4 In Setup → Permission Sets → AAR_Admin: verify Object Permissions show Read/Create/Edit/Delete/View All/Modify All for all AAR_ objects. All CRUD checkboxes enabled for all 21 AAR objects. Redeploy AAR_Admin.permissionset-meta.xml
C5 Setup → Custom Permissions: confirm AAR_Evaluator exists. Setup → Public Groups: confirm AAR_Evaluators group exists. Both visible and active. Redeploy from customPermissions/ or groups/ directory.
