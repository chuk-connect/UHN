Naming Discrepancy Resolved (Zero Breaking Change). The BH-1126 spec references AAR_Record__c as the main AAR record object. The actual sandbox object is UHN_AAR__c (Label: "AAR Record"). Renaming would break all existing layouts, Apex classes, triggers, LWCs, and list views — so the spec mapping is resolved at the concept level: all BH-1126 field history requirements are applied to UHN_AAR__c. This is documented as a planned API-name migration per BH-987 (not in current scope). No functionality was broken.
ℹ️
Data Protection Framing (per Apr 24, 2026 sprint decision): Shield = audit + field history + 7-year retention. Hourly org backups = point-in-time recovery. These are complementary mechanisms — Shield is NOT the data recovery backstop.

Reference — Sample Audit Queries
-- All field changes for a specific UHN_AAR record
SELECT Id, Field, OldValue, NewValue, CreatedById, CreatedDate
FROM UHN_AAR__History WHERE ParentId = :aarRecordId
ORDER BY CreatedDate DESC;

-- Attestation sign-offs in the last 30 days
SELECT ParentId, OldValue, NewValue, CreatedById, CreatedDate
FROM UHN_AAR__History WHERE Field = 'Attested_By__c'
AND CreatedDate = LAST_N_DAYS:30 ORDER BY CreatedDate DESC;

-- Evaluation rating changes
SELECT ParentId, Field, OldValue, NewValue, CreatedById, CreatedDate
FROM AAR_Evaluation__History WHERE Field = 'Rating__c'
ORDER BY CreatedDate DESC;
